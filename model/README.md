# 트렌드 레이더 모델 (2차)

네이버 검색량으로 "지금 급등한 키워드가 13주 뒤(이달의 맛 출시 시점)에도 수요가 남을까"를 예측한다.

- `export_radar.py`: 학습, 검증, 앱 화면 데이터 `src/lib/trend-data.ts` 생성 (2차 기준은 이 파일)
- `BR_trend_radar_model.ipynb`: 1차 분석 노트북 (Colab용, 키워드 79개 기준. 2차 변경은 반영 안 됨)
- `data/`
  - `datalab_weekly.csv`, `datalab_ingredients_weekly.csv`, `datalab_br_ingredients_weekly.csv`: 1차 키워드 79개 주간 검색량
  - `datalab_wiki_weekly.csv.gz`: 위키백과 디저트 목록 키워드 (뜬 적 없는 디저트 포함)
  - `datalab_overseas_weekly.csv.gz`: 해외 바이럴 디저트
  - `datalab_related_weekly.csv.gz`, `related_keywords.csv`: 네이버 연관 검색어로 찾은 디저트, 재료, 상표 198개
  - `datalab_age_weekly.csv.gz`: 급등이 있는 키워드의 연령별(13~29세, 30세 이상) 주간 검색량
  - `searchad_monthly.csv`: 검색광고 API 최근 한 달 실제 검색 수 (PC + 모바일)
  - `chronos2_train.npz`: 학습용 급등마다 Chronos-2의 13주 뒤 예측(하위 10%, 중간, 상위 10%)과 요약 벡터(예측 칸 768 + 요약 칸 768, float16)
  - `chronos2_live.npz`: 화면에 뜨는 최근 26주 급등의 같은 값
  - Chronos-2 값은 Hugging Face에 접속되는 컴퓨터에서 미리 계산해 넣었다 (radar_v2/step22, step23, step25). 두 파일이 없으면 Chronos 없이 지난 모델로 만든다
  - 데이터랩 값은 모두 키워드(와 연령 그룹)마다 최고 주 = 100

다시 만들기 (레포 최상위에서, 3~5분):

```
pip install pandas numpy scipy scikit-learn
python model/export_radar.py
```

## 규칙

| | 1차 | 2차 |
|---|---|---|
| 키워드 | 79개 (뜬 트렌드 위주) | 611개 (품질 필터 통과, '소한'은 절기 검색이라 제외) |
| 급등 | 직전 12주 평균의 1.5배 | 1.5배 + 실제 검색 수로 환산해 평소 흔들림의 3배 이상 |
| 버팀 정답 | 13주 뒤 검색량이 급등 주의 50% 이상 | 급등으로 늘어난 부분의 50% 이상이 12~14주 3주 평균에도 남음 |
| 힌트 | 검색 곡선 8개 | + 검색 규모 2개 + 30세 이상 검색 곡선 3개 + Chronos-2 예측 3개 + Chronos-2 선형 탐침 확률 1개 |
| 모델 | 랜덤 포레스트 | 스태킹: 선형 탐침(요약 벡터 -> PCA 32 -> 로지스틱 회귀)이 낸 확률을 랜덤 포레스트 힌트로 추가 |
| 시험 | 키워드 5묶음 (시점 섞임) | 키워드 5묶음 + 2024, 2025년 이후 미래만 시험, 묶음 5번 반복 |
| 후보 규모 | 전성기 대비 20% 이상 | 실제 검색 주 1,000회 이상 |

1차 버팀 기준은 평소 수준으로 돌아가기만 해도 버팀이 되는 경우가 많아(버팀 비율 65%) 바꿨다.
품질 필터: 실제 검색 수 없음, 최근 4주 검색 0(환산 불가), 값 있는 주 2년 미만, 첫 검색 이후 0인 주 20% 초과는 제외.

## 성능 (새 트렌드 급등 2,794건, 반복형 제외)

| | 균형 정확도 | 꺼질 것 맞힘 | 버틸 것 맞힘 |
|---|---|---|---|
| 레이더 + Chronos-2 스태킹 (화면에 사용) | 0.73 | 90% | 58% |
| 레이더 + Chronos-2 예측 힌트 | 0.71 | 89% | 56% |
| Chronos-2 선형 탐침만 | 0.73 | 85% | 63% |
| 지난 레이더 (Chronos 없이, 30세 이상 힌트 포함) | 0.64 | 86% | 44% |
| 기존 규칙 (뜨는 데 5주 이하면 못 버팀) | 0.53 | | |
| 찍기 | 0.50 | | |

- 반복형까지 포함하면 0.82 (꺼질 것 92%, 버틸 것 71%). 화면 맨 위 숫자는 이 값이고, 새 트렌드 숫자를 같이 적는다.
- Chronos-2를 더해서 고친 것: 명절 전 반짝 뜨는 전통 간식(약과, 월병, 양갱 등)을 '버팀'으로 잘못 본 경우, 제철이 막 시작된 재료(애플망고, 계란빵 등)를 놓친 경우.
- 새 트렌드 중 13주를 버틴 건 18%. 레이더는 '버틸 것' 보증보다 '꺼질 것' 거르기에 강하다.
- 1차 점수(0.75)는 같은 키워드가 학습과 시험에 섞이고 버팀 기준이 느슨해서 높게 나온 것.
- 버팀 기준을 30%, 70%로 바꿔도 정확도는 0.62~0.66으로 비슷했다.
- 시도했지만 효과 없던 힌트: 쇼핑 클릭(네이버 쇼핑인사이트), 디저트 유형과 종류, 급등한 달, 과거 급등 이력, 명절과 기념일. 연관 검색어로 키워드를 늘린 것도 정확도는 그대로였다.
- 30세 이상 힌트는 10번 반복 모두에서 점수를 올린 유일한 힌트 (+0.017). 효과는 대부분 '30세 이상의 평소 수요'에서 나온다.

## 제안 규칙

- 반복형: 시즌 재출시. 주의 표시: 단기 대응.
- 확률 60% 이상 + 주 1,000회 이상: 이달의 맛 후보. 단, 기존 제품 이름(연관 검색어, 위키백과 목록에서 '상표'로 분류)은 관찰로 두고 콜라보 검토.
- 확률은 높지만 주 1,000회 미만, 또는 확률 40~60%: 관찰. 40% 미만: 단기 대응.

## 다가오는 시즌

반복형은 검색이 튀고 나서 잡으면 올해 출시가 늦다. 그래서 데이터 기준일 + 13주가 속한 달과 그다음 달에
매년 정점을 찍는 반복형 재료를 급등 전에 따로 보여 준다 (`season`). 기준일이 바뀌면 달도 따라 바뀐다.

## 주의 표시

30세 이상 검색 비중이 50% 미만인 디저트(20대 위주)에서 30세 이상 검색이 20대보다 훨씬 더 오른 급등(상위 25%)은
과거 7%만 13주를 버텼다 (새 트렌드 평균 18%). 2016~2021년과 2022~2026년, 버팀 기준 30~70% 모두에서 같은 패턴.
이유는 아직 모른다. 명절 반짝, 20대 사이 끝물, 검색만 하고 안 사는 경우는 데이터로 확인해 보니 아니었다.
30세 이상 비중은 전체 검색 곡선을 '13~29세 곡선 x a + 30세 이상 곡선 x b'로 맞춰 추정한다.

곡선 모양 군집(K-means 4묶음)과 유형 이름(단발형, 완만형, 반복형)은 1차와 같다. 유형 이름은 `src/lib/data.ts` 의 `ShapeName` 과 같다.
